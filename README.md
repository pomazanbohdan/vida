# VIDA

**Розмови, знання та справи — в одному просторі.**

VIDA — супер-ап у розробці, який має об’єднати спілкування, нотатки й керування проєктами в особистих і спільних просторах. Ідея проста: рішення з розмови стає нотаткою, а нотатка — задачею, зберігаючи посилання на початковий контекст.

**[Сайт проєкту та інтерактивне демо](https://pomazanbohdan.github.io/vida/)** · [Google Slides](https://docs.google.com/presentation/d/1DmRJqWwhgBMitWEkcKHw-hjjThPEYpoMSlGXy-HZ8f8/edit) · [Презентація PPTX](presentation-output/VIDA-developers-5min.pptx) · [Документація](docs/README.md)

## Для чого VIDA

- **Особистий простір:** власні розмови, знання, файли та плани.
- **Спільний простір:** командна робота з явними правами доступу до ресурсів.
- **Пов’язаний контекст:** повідомлення, документ і задача посилаються одне на одного.
- **Local-first:** локально доступні дані та робота на пристрої; обмін змінами відновлюється за наявності доступного авторизованого вузла.
- **Композиція застосунків:** спеціалізовані пакети використовують стандартні можливості й додають власні дані та процеси.

## Заплановані можливості

Перший продуктовий набір охоплює **Messenger**, **Notes / Knowledge** та **Projects**. Контакти, календар і файли є спільними можливостями ядра. Personal Space і Shared Space визначають контекст роботи та доступу.

CRM, управління ОСББ, запис до бізнесу, маркетплейси й інтеграції зовнішніх платформ — напрями розвитку екосистеми. Наприклад, City Portal може мати власний сайт і backend та окремий застосунок усередині VIDA. Ці сценарії не означають наявності готових бізнес-застосунків у поточному репозиторії.

Докладніше: [склад першої версії](docs/01-product/v1-replacement-bundle.md), [композиційна модель](docs/01-product/composable-workspace-model.md), [межі продукту](docs/01-product/product-boundary.md).

## Архітектурний задум

| Рівень | Призначення |
| --- | --- |
| Flutter-клієнти | Заплановані інтерфейси Android, iOS, Windows і Web |
| Спільне ядро Rust | Правила ресурсів, ідентичності, доступу та перевірки операцій |
| Локальне збереження й синхронізація | Збереження змін, перевірка історії та узгодження даних між пристроями |
| Iroh | Захищений транспорт між вузлами; права й значення даних визначає VIDA |
| AppPackage / AppInstance | Опис пакета та його конкретна активація у вибраному Space |

Прямі з’єднання та relay мають різні транспортні ролі. Relay пересилає трафік між доступними пристроями й не є поштовою чергою для офлайн-доставки. Доставка операції також не дорівнює її прийняттю бізнес-процесом.

[Архітектура транспорту й синхронізації](docs/03-architecture/transport-sync-architecture.md) · [Архітектурні рішення](docs/03-architecture/decisions/README.md) · [Контракт пакетів](docs/04-specifications/app-package-runtime-baseline.md)

## Поточний стан

**VIDA перебуває на ранньому етапі реалізації. Готового користувацького релізу ще немає.**

- У репозиторії є документація, архітектурні рішення, специфікації та дослідження.
- У `crates/vida-core` є початкова Rust-реалізація компонентів controller, recovery і storage та тести. Це не повна реалізація описаної платформи.
- Презентаційний сайт працює; інтерактивний сценарій «розмова → нотатка → задача» є концептом інтерфейсу.
- Клієнти, повна синхронізація та екосистема застосунків потребують подальшої реалізації й перевірок.

Статуси окремих контрактів і невирішені питання наведено в [карті стану](docs/00-governance/contour-status.md) та [переліку відкритих питань](docs/00-governance/open-questions.md). Наявність специфікації або тестового сценарію сама по собі не підтверджує готовність функції. Матеріали досліджень не стають затвердженими рішеннями автоматично.

## Як долучитися

Потрібні внески в **Rust, Flutter, тестування, UX і документацію**.

1. Ознайомтеся з [документацією](docs/README.md) та [правилами роботи](docs/00-governance/working-agreement.md).
2. Перегляньте [issues](https://github.com/pomazanbohdan/vida/issues) і погодьте невелику конкретну зміну.
3. У pull request опишіть результат, межі зміни та спосіб перевірки.

Для перевірки поточного Rust-ядра, за наявності встановленого Rust toolchain:

```sh
cargo test -p vida-core
```

Інструкції роботи з презентаційним сайтом: [`website/README.md`](website/README.md).
