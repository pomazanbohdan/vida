## Findings

1. **Medium — chat publication proof points to the wrong open question.** `native-client-requirements.md:21` assigns publication proof/clock to `OQ-0034`, while AD-27 and its implementation gate explicitly assign publication receipt, tie ordering and written-at metadata to `OQ-0065`. `OQ-0034` may still cover generic SyncLog rules, but the client requirement should cite `OQ-0065` for this operation family (or both with separate scopes). This is a local-document traceability finding, not an external standard mandate. Confidence high.
2. **Low — prefer Temporal's reference documentation over an AI-patterns landing page.** The current `effect-execution-constraints.md` citation does support the at-least-once Activity/idempotency claim, but [Temporal Retry Policies](https://docs.temporal.io/encyclopedia/retry-policies) states the retry behavior and Activity re-execution expectation more directly. Optional source substitution; no product rule change. Publisher Temporal, n.d.; accessed 2026-09-20. Confidence high.

## Verified claims and limits

- [Iroh `Connection`](https://docs.rs/iroh/latest/iroh/endpoint/struct.Connection.html), n0-computer 1.2.0, accessed 2026-09-20: a sender can know bytes reached the remote QUIC stack while data acknowledged there may still be dropped before delivery to the remote application. Thus transport ACK cannot prove VIDA sync apply, domain acceptance or an external effect. The Iroh docs do **not** define a VIDA application receipt. Confidence high.
- [Automerge Rust Sync Protocol](https://automerge.org/automerge/automerge/sync/index.html), Automerge, n.d., accessed 2026-09-20: peers exchange document changes/heads over a reliable in-order stream; this supports the effect document's narrow history-exchange description. It provides no third-party email/booking completion proof. Confidence high.
- [RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2), IETF, June 2022, accessed 2026-09-20: a client SHOULD NOT automatically retry a non-idempotent request absent known idempotent semantics or evidence the first request was not applied. This is about HTTP request behavior, not a VIDA-wide authority protocol or proof of exactly one external effect. Confidence high.
- [Stripe Idempotent Requests](https://docs.stripe.com/api/idempotent_requests), Stripe, n.d., accessed 2026-09-20: a repeated POST with the same idempotency key can return the first result; keys can be removed after at least 24 hours, and reuse after pruning starts a new request. The effect document correctly treats this as provider-specific and time-bounded. Confidence high.
- [Temporal AI Engineering Patterns](https://go.temporal.io/platform-hub/ai-engineering/ai-patterns) and [Retry Policies](https://docs.temporal.io/encyclopedia/retry-policies), Temporal, n.d., accessed 2026-09-20: an Activity may run again on retry; a durable workflow alone does not make its write-side external effect exactly once. Temporal is a reference, not an adopted VIDA dependency. Confidence high.
- [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html), [AI Agent Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html), and [MASVS-PRIVACY-1](https://mas.owasp.org/MASVS/controls/MASVS-PRIVACY-1/), OWASP, n.d., accessed 2026-09-20: per-request authorization/deny-by-default, scoped agent tools/explicit sensitive-operation authorization, and sensitive-data minimization support the negative-security tests. They do not mandate AD-25's exact action-type opt-in, a profile-visible online-device count, its proof/TTL, a two-device quorum, or the UI word «синхронізовано». Those are VIDA decisions/open questions. Confidence high.
- [Matrix Client-Server API v1.19](https://spec.matrix.org/v1.19/client-server-api/), Matrix.org, n.d., accessed 2026-09-20: the updated presence document correctly says presence, room events and device-list updates are distinct *semantics* while presence can travel in `/sync`. Matrix aggregates per-device data into per-user presence via a homeserver; it is not a ready model for VIDA's profile device counter. Confidence high.

AD-26/27 appropriately defer sync-capability proof, partition freshness, anonymous-profile visibility and publication ordering to `OQ-0064`/`OQ-0065`. A displayed 13:00 publication example is a VIDA product rule, not a clock or total-order guarantee supplied by Iroh, Automerge or Matrix. Keep production conformance gated until those proofs are specified and tested.
