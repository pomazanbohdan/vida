## Findings

1. **Medium — stale Matrix reference and imprecise transport wording.** `sync-presence-status-model.md` cites Matrix Client-Server API v1.18, while the official current stable release is v1.19. Matrix defines `m.presence` as a per-user event aggregated by a homeserver from per-device signals; presence can be carried inside `/sync`. Thus “presence events separately from sync” should become “a distinct presence signal within the client/server model, including `/sync`, separate from room-event and device-list semantics.” Do not infer a Space-wide online-device counter or its privacy policy from Matrix. Fix: link v1.19 and clarify that distinction. Sources: [Matrix stable index](https://spec.matrix.org/latest/) (v1.19 listed), [Matrix v1.19 Client-Server API, Presence and `/sync`](https://spec.matrix.org/v1.19/client-server-api/), publisher Matrix.org, n.d.; accessed 2026-09-20. Confidence high.
2. **Medium — freshness metadata lags content.** `blob-store-contract.md` and `effect-execution-constraints.md` have `last_updated: 2026-09-19` despite rules and OWASP review marked 2026-09-20. Set metadata to the actual edit date to avoid a misleading currentness signal. This is a local-document observation, not an external-source finding. Confidence high.

## Source-backed checks and limits

- **Iroh named version:** The spine's Iroh 1.2.0 decision baseline matches the live [docs.rs iroh crate release listing](https://docs.rs/crate/iroh/latest), which listed 1.2.0 dated 2026-09-09 when accessed. The official [Iroh endpoint API](https://docs.rs/iroh/latest/iroh/endpoint/index.html) is a connectivity mechanism; it does not define VIDA authority acceptance, causal conflict priority, rights or effect finality. AD-13/22/24 properly own those above transport. Publisher n0-computer / docs.rs; accessed 2026-09-20. Confidence high.
- **Automerge conflict boundary:** [Automerge Conflicts](https://automerge.org/docs/reference/documents/conflicts/) says concurrent same-key writes retain all alternatives through `getConflicts`, but ordinary reads show a deterministic winner, and a later assignment can clear the library conflict. Therefore AD-22's explicit no-winner business projection and prohibition on silent clearing are VIDA-specific safeguards, not built-in Automerge behavior. Publisher Automerge, n.d.; accessed 2026-09-20. Confidence high.
- **Authorization:** [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) recommends deny by default, least privilege and permission validation on every request. AD-16's seven-day shared-read interval and AD-22/23's variant authorization are VIDA choices; OWASP does not set their timing, acceptance evidence, peer topology or exact offline read semantics. Publisher OWASP, n.d.; accessed 2026-09-20. Confidence high.
- **Sensitive blobs and presence:** [MASVS-STORAGE-1](https://mas.owasp.org/MASVS/controls/MASVS-STORAGE-1/) says mobile apps securely store sensitive data; [MASVS-PRIVACY-1](https://mas.owasp.org/MASVS/controls/MASVS-PRIVACY-1/) minimizes sensitive-data/resource access. Both citations fit as security principles, not as a prescribed pin lifetime, safe retention frontier, presence TTL or online-device-count UX. MASVS is mobile-specific; Windows client checks need their own platform evidence. Publisher OWASP, n.d.; accessed 2026-09-20. Confidence high.
- **Agents and effects:** [OWASP AI Agent Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html) recommends scoped tools, explicit authorization for sensitive operations and human-in-the-loop for high-risk actions. AD-25's per-action opt-in is a stricter VIDA policy, not an OWASP universal rule. AD-24's source-domain confirmation gate is likewise a VIDA safety policy; it cannot prove no unseen disconnected branch exists, and AD-24 correctly defers exact confirmation/compensation. Publisher OWASP, n.d.; accessed 2026-09-20. Confidence high.

No source reviewed supplies a universal “globally final” peer-to-peer acceptance certificate, seven-day rights-reconciliation interval, or safe blob-GC frontier. Keep `OQ-0033`, `OQ-0034`, `OQ-0045`, and `OQ-0053` open until VIDA specifies and tests those contracts.
