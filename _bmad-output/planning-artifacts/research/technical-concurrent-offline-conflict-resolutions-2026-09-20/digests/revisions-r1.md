# Revision and precondition reference digest — 2026-09-20

- Claim: Independent disconnected users/agents can resolve the same CouchDB conflict differently, producing further conflicts on replication. Source: [CouchDB Technical Overview](https://docs.couchdb.org/en/stable/intro/overview.html), Apache CouchDB, publication date n.d., accessed 2026-09-20; confidence high.
- Claim: CouchDB replicates conflicting revision leaves, selects a deterministic visible winner, and rejects stale `_rev` updates with 409 on a single node. Source: [CouchDB replication conflicts](https://docs.couchdb.org/en/stable/replication/conflicts.html), Apache CouchDB, n.d., accessed 2026-09-20; confidence high. Its visible-winner policy and single-parent resolution are not VIDA policy.
- Claim: Git merge commits record multiple parent tips and overlapping edits may require manual conflict resolution; a later unseen branch needs another merge. Sources: [git-merge](https://git-scm.com/docs/git-merge), [Git FAQ](https://git-scm.com/docs/gitfaq), Git project, n.d., accessed 2026-09-20; confidence high for Git semantics, analogy only for VIDA.
- Claim: HTTP If-Match is a precondition against lost updates when an online authority can compare entity tags and return 412; it cannot itself order isolated equal peers. Source: [RFC 9110 §13.1.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1), IETF, June 2022, accessed 2026-09-20; confidence high for RFC behavior; VIDA limitation is inference.
- Design inference, not a source fact: incompatible resolutions `R1(A,B)` and `R2(A,B)` with no causal edge create new unresolved heads `{R1,R2}`; an unseen incompatible `C` adds another head. Do not claim global finality before reconciliation. If payloads are semantically identical, projection may collapse them only under an explicit operation-family rule.
