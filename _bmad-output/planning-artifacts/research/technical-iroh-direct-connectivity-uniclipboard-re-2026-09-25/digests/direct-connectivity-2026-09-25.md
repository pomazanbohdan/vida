# Direct connectivity and UniClipboard — source digest

Accessed 2026-09-25. Publisher dates unavailable for living docs; Iroh API inspected at 1.2.0. Project documents guided the decision questions, not the external factual claims.

| Claim | Primary source | Confidence / caveat |
| --- | --- | --- |
| Iroh can dial a reachable native endpoint directly when given its current IP address and EndpointId, without relay. `RelayMode::Disabled` exists. | [Iroh 1.2 endpoint API](https://docs.rs/iroh/latest/iroh/endpoint/struct.Builder.html); [Iroh 1.2 source](https://docs.rs/iroh/latest/src/iroh/endpoint.rs.html) | High for native API; actual cross-network reachability is environment-dependent. |
| Local mDNS lookup finds peer addresses on one LAN, is opt-in, and allows direct connection without relay. | [Iroh mDNS guide](https://docs.iroh.computer/connecting/local-address-lookup) | High for documented capability; Wi-Fi client isolation remains a risk. |
| Ordinary Iroh NAT traversal starts with relay coordination, tries simultaneous direct UDP and falls back to relayed traffic when direct fails. | [Iroh NAT traversal](https://docs.iroh.computer/concepts/nat-traversal); [Iroh relay concepts](https://docs.iroh.computer/concepts/relays) | High for documented mechanism; vendor's approximate success ratio is not a VIDA performance guarantee. |
| DNS/Pkarr, mDNS and DHT are separate address-lookup paths; DHT is opt-in and removes a hosted lookup server, not the need for reachable addresses. | [Iroh address lookup](https://docs.iroh.computer/concepts/address-lookup); [Iroh DHT guide](https://docs.iroh.computer/connecting/dht-address-lookup) | High for mechanism. |
| Current browser Iroh has no direct paths; every browser connection uses relay because browser sandbox lacks arbitrary UDP. | [Iroh WebAssembly/browser guide](https://docs.iroh.computer/languages/wasm-browser) | High for current documented behavior; recheck on Iroh upgrade. |
| Iroh relay server can be self-hosted using official `iroh-relay` package/binary; relay forwards E2EE traffic but sees connection metadata. | [Iroh self-hosting guide](https://docs.iroh.computer/iroh-services/relays/self-hosted); [Iroh security/privacy](https://docs.iroh.computer/concepts/security-privacy) | High for capability; self-hosting guide itself warns configuration may lag current code. |
| UniClipboard separates trust, discovery and transport; desktop pairing uses invite + passphrase and PAKE, discovery uses LAN mDNS, HTTPS rendezvous and cached addresses; Iroh moves data direct when possible, relay otherwise. | [UniClipboard pairing and sync](https://docs.uniclipboard.app/guides/pairing) | High for published design, not an independent runtime test. |
| UniClipboard LAN-only mode disables Iroh relay and n0 DNS; already-paired devices sync on LAN without WAN, while first-time code pairing still uses UniClipboard rendezvous. | [UniClipboard FAQ](https://docs.uniclipboard.app/help/faq) | High for published product behavior; distinguish no-relay transport from zero-server bootstrap. |
| UniClipboard's documented current mobile companion is HTTP to desktop, not Iroh P2P/mobile-to-mobile; Engine has mobile bindings and an experimental path, so released mobile parity is not established. | [UniClipboard pairing and sync](https://docs.uniclipboard.app/guides/pairing); [Engine README](https://github.com/UniClipboard/Engine) | High for documentation distinction; release-specific device test remains necessary. |
| Iroh endpoint tickets can bootstrap via QR without central coordination, but are reusable, can go stale and reveal included IP addresses. | [Iroh tickets](https://docs.iroh.computer/concepts/tickets) | High for documented semantics; VIDA one-time invites need their own authorization and expiry. |
| Native direct peers reveal IP addresses to each other; relay sees endpoint/connection metadata but not E2EE content. | [Iroh security/privacy](https://docs.iroh.computer/concepts/security-privacy) | High for documented threat boundary. |

Leads: Test an Iroh 1.2 native `Minimal + mDNS + RelayMode::Disabled` profile with WAN severed; then own-relay fallback across distinct NATs; separately verify Flutter Web/Wasm relay path. Do not infer VIDA application receipts or durable sync from transport reachability.
