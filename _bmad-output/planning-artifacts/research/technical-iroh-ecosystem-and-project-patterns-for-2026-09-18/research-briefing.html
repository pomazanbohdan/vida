Виконавче резюме

VIDA приймає Iroh 1.2 як основну транспортну платформу: mutually authenticated E2E-encrypted QUIC, Address Lookup, NAT traversal, direct path із relay fallback та ALPN routing [1][2][3][40]. Iroh не є месенджером, authorization model, database або offline mailbox.

VidaNodeHost володіє Router, endpoint pool і network lifecycle. Persistent endpoint обслуговує звичайний/federated profile; anonymous/session flows отримують ephemeral endpoints. Domain modules залежать від VIDA interfaces, а не від конкретних 0.x crates.

Ключове рішення: direct Iroh — fast path; окремий E2E-encrypted durable delivery service — offline path. Iroh relay stateless і не зберігає messages [33]. Direct і mailbox paths переносять той самий signed operation envelope з atomic local log+outbox.

high core/relay/Delta boundaries. medium 0.x protocols. low–medium сторонні apps.

Що стабільне

verified core
  • EndpointId is Ed25519; QUIC mutually authenticated/E2E encrypted [2][40].
  • Router dispatches ALPN [3].
  • Signed DNS/Pkarr lookup; local/DHT opt-in [4].
  • Relay→hole punch→direct migration [5].
separate 0.x
  • blobs 0.103; gossip 0.101 [9][10].
  • docs 0.100 is blobs+gossip meta-protocol [11][39].
  • Core stability does not stabilize them.
  • Blobs maturity guidance is contradictory [38].

Browser WASM is relay-only [7]. FFI covers stable core for Swift/Kotlin/Python/Node; blobs/docs/gossip are excluded [8]. 0.x components remain pinned, replaceable adapters with independent version tests.

Offline delivery та identity

  • Same signed operation ID/envelope on direct and mailbox paths.
  • Atomic local log + outbox; mailbox is cache, not authority.
  • ACK: accepted → stored → applied → read.
  • Idempotency, causal order, multi-device fan-out, TTL, quota, retry, deletion.
  • Separate ADR: single/replicated mailbox, keeper peers or authoritative service.

Revocation: a new epoch blocks future access; it cannot revoke plaintext already replicated.

Prototype gates

  1. Core node: Router, persistent+ephemeral profiles, rotation/recovery/unlinkability.
  2. Version axes: core, adapter, ALPN major, schema, state, FFI; rolling upgrade/rollback/restore.
  3. Offline: two delivery nodes, direct/mailbox race, crash, dedupe, order, ACK, failover.
  4. Space security: root of trust, admin policy, concurrent grants/revokes, partition and future-only revocation.
  5. Local-first state: concurrent edits, snapshot, repair, tombstones and GC.
  6. Blob security: hash model, object keys, manifests, expiring tickets, delete/rekey.
  7. Separate browser, Android and iOS gates.
  8. Address Lookup outage/stale/rollback/compromise.
  9. Threat model: malicious member, stolen key, compromised node, metadata and abuse.
