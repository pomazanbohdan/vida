## Iroh-blobs 0.103 completion boundary (focused check, 2026-09-23)

- The [protocol](https://docs.rs/iroh-blobs/0.103.0/iroh_blobs/protocol/index.html) validates transferred ranges; the [store API source](https://docs.rs/iroh-blobs/latest/src/iroh_blobs/api/proto.rs.html) distinguishes `NotFound`, `Partial` and `Complete` (the checked `latest` page identifies version 0.103.0). `Complete` establishes blob availability in that store, not a committed VIDA File ID, relation, outbox intent or delivery receipt.
- [Import `Done(TempTag)`](https://docs.rs/iroh-blobs/latest/src/iroh_blobs/api/proto.rs.html) says bytes are available and temporarily protected. A [Batch](https://docs.rs/iroh-blobs/latest/iroh_blobs/api/blobs/struct.Batch.html) protects in-flight content until its temporary tags are released; un-upgraded content then becomes GC-eligible. This is not evidence of VIDA's durable retention frontier.
- **Candidate integration gate, not library guarantee:** test verified bytes → retained/pinned bytes → atomic VIDA manifest/relation/outbox commit as distinct milestones. Kill after each milestone; after restart, either recover the complete authorized File or show a truthful pending/failure state, never “saved locally” for an uncommitted attachment. The selected provider still needs this application-level proof.

## Development and issue signals, kept separate from features

- The dated [storage snapshot](storage-sync-r3-luna.md) counted Wyrd `660/660` raw default-branch commit API records over 30/90 days. This is unusually dense and includes non-feature work; concrete export/recovery commits are stronger evidence than the count. The [current upstream status](https://github.com/control-aesir/wyrd#status) still calls the product pre-alpha and names automatic peer repair and GC as pending.
- The dated [network snapshot](network-mobile-r3-luna.md) counted RDS `87/87` raw commit records, but its public history spanned about two days. Rapid PR closure does not establish sustained maintenance, first response, independent review or defect resolution. The [current README](https://github.com/NDDev-OpenNetwork/remote-device-sync#readme) documents broad daemon/network/file capabilities.
- The [Ringdrop repository](https://github.com/rikettsie/ringdrop) currently exposes 5 issues, 0 PRs and 227 historical commits in its GitHub navigation. These are **snapshot totals**, not 30/90-day meaningful-commit counts or issue-response measurements; issue severity and resolution need case-level inspection.
- The [iroh-blobs repository](https://github.com/n0-computer/iroh-blobs) currently exposes issue/PR activity and its own production-quality warning. Exact recent meaningful-commit counts and issue response times were not verified in this pass because unauthenticated GitHub API queries were rate-limited; do not infer inactivity from that gap.

**VIDA implication:** Keep `iroh-blobs` and alternative verified transfer in the same `SPEC-BLOB-STORE` conformance gate: interrupted transfer, hash corruption, low disk space, ACL/revocation, encrypted payload, selective download and last recoverable copy. Wyrd and Ringdrop supply useful implementation patterns; neither is evidence that VIDA's full file policy can be adopted unchanged. No candidate is selected here.
