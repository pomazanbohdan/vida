## Comparative implications

- **E2EE/group rotation:** Arachne supplies the most standards-based group-security code path in these four (OpenMLS), but its extremely young implementation warrants adversarial add/remove/epoch/recovery tests. freeq has greater operational breadth and faster visible feature throughput, yet explicitly distinguishes app E2EE from Iroh transport and flags legacy ENC2 as broken; EG1 requires independent protocol review and vectors.
- **Durable outbox:** Proscenium is the direct SQLite/outbox/retry pattern to falsify under process death and ACK ambiguity. It has no observed recent implementation movement after a cutoff-edge update; do not read this alone as a verdict on code quality.
- **Calls/media:** iroh-live is a room/MoQ/Gossip boundary experiment; Proscenium shows separate signaling and media paths; neither by itself proves post-revocation access control, secure admission or device lifecycle behavior. iroh-live's open CPU-spin report makes load/backpressure tests particularly important.
- **Workspace ACL:** Arachne's MLS and workspace-delivery seam, plus freeq's auth/session admission surfaces, suggest tests rather than an imported ACL implementation. freeq issues #102–105 are useful reported negative cases. Verify against present code before treating any report as a current defect.
- These observations nominate prototype gates only; they do not select a production stack. Commit counts, popularity and semver are not stand-alone quality measures.

## Method / limits

GitHub REST primary sources queried 2026-09-23 UTC: `/repos/{owner}/{repo}/commits?since=...&per_page=100`, `/issues?state=all`, `/pulls?state=all`, and individual issue/PR pages; repository manifests, code and pinned revision links as cited in r1/r2. GitHub Issues search query `is:issue is:closed closed:>=2026-06-25` returned closed-issue counts 0 Arachne, 16 freeq, 0 iroh-live, 0 Proscenium; linked query URLs in the table encode that filter. These are issues only, not PRs. Open issue/PR figures are separate point-in-time counts from the r2 repository-page snapshot (2026-09-23); closed PR totals are not conflated with the issue counts. For freeq, both 30d and 90d REST commit pages reached 100; a page-2 retry was blocked by GitHub API rate limit, so report `at least 100`, not an exact total. Responsiveness examples use creation-to-merge/close elapsed time for individually linked PRs, not first-response time or a representative SLA. GitHub issue update time is not proof of maintainer action. `Proscenium` cutoff dates are UTC-normalized; its latest timestamp is just 3h34m inside the 90-day window. No independent audit, maintainer interview, deployment-scale evidence, or full closed-history classification was performed.
