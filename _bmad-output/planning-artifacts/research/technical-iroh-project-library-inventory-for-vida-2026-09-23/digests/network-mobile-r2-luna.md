## VIDA prototype questions these references can answer

- Endpoint / daemon: compare Quix/Rayfish lifecycle semantics with RDS `Endpoint::close`, signal shutdown, reconnect and peer admission; add stop/revoke/process-kill/network-change checks.
- Relay/NAT: RDS multi-relay probe/failover + self-hosted relay, Rayfish direct mesh/NAT mapping, NexaPipe and iroh-tunnel direct/relay routes; explicitly test symmetric NAT and force-relay fallback.
- Mobile/TUN: compare selective-domain VpnService handover in Nexa with Rayfish's Android mesh wrapper and BLE adapter power recovery; make OS permission/revoke/background behavior device gates.
- App protocols: RDS custom services and NexaPipe routing are breadth references. Their independent custom ALPNs/protocols are not wire-compatible by default.
- Blob/transfer: Rayfish uses `iroh-blobs` fs store; RDS sync adds FastCDC+BLAKE3 resumability. Validate per-chunk and final-object hashes, cancellation, resume after process death, size caps and authorization separately.
- Compatibility/license: `iroh-ble-transport` depends on unstable custom-transport Iroh APIs and AGPL terms; Nexa uses MIT; RDS is AGPL-only. Confirm current transitive lock graph and intended reuse model before any prototype dependency decision.
