# Encrypted backup completion and verification — source digest

Accessed: 2026-09-29. Product documentation pages generally have no stated publication date; andOTP repository was archived in 2022.

- **andOTP:** Internal plain/password/OpenPGP exports are separate from copying app data. Third-party app-data copies may lack its Android Keystore key and cannot restore. Changelog records encrypted backup on entry change and a later fix for incorrectly reported backup failures. Neither source claims a read-back or restore test after every export. Sources: [README](https://github.com/andOTP/andOTP), [changelog](https://github.com/andOTP/andOTP/blob/master/CHANGELOG.md). Confidence: high for documented behavior, unverified for any implied post-write check.
- **Aegis:** Manual export and automatic backup share one vault format; importing an encrypted export requires the vault password. No documented post-write restore verification. Source: [FAQ](https://github.com/beemdevelopment/Aegis/blob/master/FAQ.md). Confidence: high for explicit behavior.
- **Ente Auth:** Password-protected export/backup, import and advice to retain a separate copy; no explicit per-write restore test documented. Source: [Ente Auth export](https://ente.com/help/auth/migration/export). Confidence: high for explicit behavior.
- **Signal:** User confirms recording the passphrase; UI can show the last successful backup. This is not evidence of a particular external file being restorable. Source: [Signal Backup and Restore](https://support.signal.org/hc/en-us/articles/360007059752-Backup-and-Restore-Messages). Confidence: high for documented flow.
- **OWASP:** Key backup, integrity and recovery planning are security requirements, but OWASP does not prescribe VIDA's UI labels or testing frequency. Source: [OWASP Key Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Key_Management_Cheat_Sheet.html). Confidence: high.
- **Inference for VIDA:** Distinguish export attempted, file written, saved bytes authenticated/parsed, and actually recoverable from an independent location. Read-back/decrypt/manifest check on the saved bytes is stronger than a write-success callback; isolated test restore is stronger still. Retain the previous known-good archive until replacement validates. Chrome's user-granted File System Access can read and write the same file handle; generic download alone may require user re-selection to verify. Source: [Chrome File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access). Confidence: medium for proposed implementation.
