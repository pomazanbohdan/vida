# Flutter Windows vs Tauri 2 Windows for VIDA

Date/accessed: 2026-09-19. Scope: Windows UI host for a local-first encrypted app whose mobile UI is Flutter and whose core is Rust. No project files were read. This is a technical selection, not an implementation claim.

## Verdict

**Flutter Windows is the baseline; Tauri Windows is a conditional alternative.** Both can host the same native Rust core. Tauri is justified only by a demonstrated desktop-specific advantage—e.g., an existing web UI/design system, a required DOM/editor/grid ecosystem, browser-UI reuse, or Tauri's integrated tray/updater surface—that exceeds the cost of maintaining a second UI and bridge. Do not infer Tauri is faster/smaller in use merely from a small installer: it depends on multiple WebView2 processes, and an offline installer may add ~127 MB. [S1][S2][S3][S4]

## Exact architectural comparison

## Required VIDA boundary

`vida-domain`/`vida-app` (pure Rust domain + use cases + encrypted repository/sync) must not import `tauri`, FRB, Dart, JS, WebView, or Windows UI APIs. `vida-flutter-adapter` maps FRB futures/streams and DTOs. `vida-tauri-adapter` maps commands/channels/state and the same DTO contract. Platform ports supply key wrapping, filesystem paths, notifications, background scheduling, network, and clock. The Rust core owns one vault writer, migrations, transaction boundaries, and durable jobs. Both UIs must treat streams as lossy observations: sequenced events plus snapshot/resync, explicit `operation_id` cancellation, idempotency keys, structured errors, and schema versions. FRB's own cancellation guidance prescribes explicit tokens; discarding a Future or stream is not a reliable domain cancellation contract. [S7][S8][S17]

For Windows secret storage, **DPAPI user scope is a possible key-wrapping adapter, not a complete vault encryption design**. Microsoft's `CryptProtectData` documentation says decryption is normally tied to the same user's logon credential and machine; `CRYPTPROTECT_LOCAL_MACHINE` can allow any user on that machine to decrypt. Evaluate Windows Hello/TPM/credential policy and recovery separately. In either host, keep long-lived keys in Rust and avoid DOM, Dart/JS persistence, events, logs, crash dumps, and clipboard exposure. [S18]

If a machine-level agent is required, isolate it as a Windows Service. Microsoft states services can execute without a logged-in user and cannot directly interact with a user; Tauri autostart is application-at-login, not service registration. The service then owns the vault and speaks authenticated, ACL-scoped local IPC to the UI; avoid dual writers. [S15][S19]

## Packaging and release coupling

- Flutter Windows: official guide covers build output, C++ runner, DLL/data/VC++ dependencies, MSIX or zip/self-managed installer; Windows code signing and update mechanism remain release-engineering choices. [S1]
- Tauri Windows: official MSI/NSIS installers and WebView2 modes; default installer downloads bootstrapper if needed. Test a clean VM with network disabled if offline installation is part of “local-first.” [S2]
- Tauri updater: signed updates mandatory, Windows exits app during installation; define pre-exit `flush/lock`, interrupted-update recovery, database schema compatibility, staged rollout, and independent Windows Authenticode signing. Updater signing does not establish OS publisher reputation. [S20][S21]
- Do not force synchronized mobile-store and Windows-updater releases. Maintain a defined N-1/N+1 persisted-schema and sync-protocol compatibility window. This is an architecture inference from independent distribution mechanisms, not a framework guarantee.

## Prototype exit criteria

Run **paired release-build spikes** implementing the same two realistic Windows journeys (vault unlock/search/edit with a large data grid or editor; background sync/notification/update). Keep Rust core, dataset, schema, tests, and hardware identical.

1. **One-core proof:** Android/iOS and both Windows spikes link the same Rust core revision; no UI-host types in core crates; contract tests pass through direct Rust, FRB, and Tauri adapters.
2. **UX capability:** compare the required desktop grid/editor, drag/drop, shortcuts, multiwindow, text selection, IME, 200–400% scaling, high contrast. Tauri must exhibit a material quality/implementation advantage to outweigh UI duplication.
3. **Accessibility:** complete flows keyboard-only, NVDA, Narrator; inspect UI Automation/semantics; record focus order and announcement defects. Do not accept DOM/Flutter-semantics support as conformance proof.
4. **Security:** adversarial WebView/bridge input validation; strict CSP and narrow capabilities; no remote script; vault lock removes accessible plaintext; same-user and cross-user Windows key tests; dump/log/clipboard leak checks.
5. **Lifecycle:** 24-hour tray/hidden run, sleep/resume, logout/login, second instance, WebView renderer crash, power/network interruption, forced termination at transaction boundaries; deterministic resync and no duplicate mutation.
6. **Updater/install:** signed MSI/NSIS and Flutter-selected installer on clean Windows 10/11 VM; offline WebView2 bootstrap; invalid update signature rejection; pre-exit flush; migration forward/rollback behavior. Installed notifications only are a Tauri constraint. [S2][S20][S22]
7. **Performance:** predeclare p95 cold start, unlock, query, 10k-row navigation, memory private bytes/working set (include all WebView2 child processes), idle CPU, battery on laptop, installer/download/installed footprint. Measure release/profile, not debug. [S3][S16]
8. **Decision gate:** choose Tauri only if it wins a product-critical criterion by a pre-agreed threshold and the extra TS UI, test, accessibility, and release workload has an owner; otherwise choose Flutter Windows.

## Research gaps

- No measured VIDA-specific cold-start, memory, latency, battery, accessibility, packaging, or team-velocity data exists in this desk study.
- Exact target Windows versions/architectures, offline enterprise policy, service need, and browser product scope are undecided inputs.
- DPAPI/Windows Hello/TPM recovery, multi-user access, and key rotation require a separate security design review.
- Current Flutter and Tauri APIs are plausible together; this study does **not** claim full integration compatibility until the pinned clean-build and lifecycle matrix passes.
