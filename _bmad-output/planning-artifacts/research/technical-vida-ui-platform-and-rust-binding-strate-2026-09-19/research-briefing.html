UI-платформи та межа Rust

Рішення, яке готуємо: чим реалізувати Android, iOS, Windows і браузер поверх спільного headless Rust-ядра — без припущення, що один UI-фреймворк має обслуговувати все.

Поточний висновок

Середня впевненість · висновок із джерел Запропонована користувачем комбінація Flutter Android/iOS + Rust core/runtime + Tauri Windows технічно узгоджена, але перевага Tauri над Flutter Windows для VIDA ще не доведена. Це робоча гіпотеза, а не ADR.

Спільним має бути семантичний Rust application facade — команди, власні DTO, типізовані помилки, operation ID, обмежені послідовні події, snapshots, lifecycle і правила сумісності. Не одна фізична ABI для кожної платформи. Flutter може використати FRB; Tauri викликає facade у Rust host і відкриває вузький IPC; браузер має окремий Wasm/API-профіль. Flutter FFI, FRB, Tauri commands, Wasm.

Наступна дія: відповісти на одне пріоритетне питання про встановлювані AppInstances у v1, погодити критерії прототипів G1–G11; реалізувати один vertical slice на Flutter mobile, Flutter Windows і Tauri Windows з тими самими Rust revision, fixtures та release-build вимірюваннями. Браузер перевіряти окремо.

Мобільний експеримент

Flutter + FRB поверх Rust facade. Перевірити OS lifecycle, доступність, bridge, захищене зберігання й notification UX.

Умовний лідер

Windows

Flutter — контрольний варіант. Tauri має показати матеріальну перевагу на реальному workflow, не на hello-world.

Відкрито

Браузер

Окремий capability/runtime-профіль; native FFI, direct Iroh path і гарантії local persistence не переносяться автоматично.

Усі 15 додаткових або точніших груп кейсів
  1. Жодного успадкованого UI-рішення: Dioxus відкликано; Flutter-прототип і .NET-shell не є approval.
  2. Один app package, кілька подань: edit/read-only/moderator/public і provider switch (G9).
  3. Повний lifecycle пакета: підпис, consent, version pin, migration, update/rollback (G9).
  4. Capability-driven UI: hidden/disabled/read-only/masked/required/allowed values/filters/confirmation/strong auth; Rust повторно перевіряє право (G4/G9).
  5. Навігація супер-апу: app stacks, account/Space switch, 10–20 apps, responsive layout (G10).
  6. Місто/бізнес із кількома входами: одне джерело, кілька placements і без tenant leak (G11).
  7. Server success ≠ offline mobile proof: однакова authority семантика на site/bot/client плюс окремі local/P2P checks (G1/G11).
  8. Великі розмови й backpressure: selective sync, bounded events, virtualization, resync_required (G2/G10).
  9. Durable reminders: due під час shutdown, catch-up і без дублювання (G10).
  10. Node/capability profiles: Full/Mobile/Browser; constrained edge відкладено (G7/G11).
  11. Browser gateway проти relay/Wasm: однакові permission/command outcomes, різні trust та storage limits (G7).
  12. Offline schema/index rebuild: стара schema, corrupted projection, безпечний прогрес відновлення (G8/G9).
  13. Windows boundary topology: Tauri in-process host проти sidecar лише за реальної lifecycle/isolation потреби (G2/G5).
  14. Delta Chat не dependency: Chatmail/SMTP/IMAP рекомендацію скасовано після відмови від email.
  15. Canonical resource/provider semantics: той самий ID, schema, permission і conflict result через Flutter/Tauri/file/server provider (G1/G9).

Встановлюваний AppInstance ≠ виконуваний Flutter plugin

У продуктовій вимозі «встановити застосунок у супер-ап» треба розділити три шари. Flutter package guide описує plugin code як частину client build; deferred components завантажують попередньо оголошені code/assets, але новий Android code вимагає rebuild/upload усього AAB. Тому deferred loading не доводить довільний post-release executable marketplace.

1 · Declarative package

Перший feasibility gate Підписані schema/layout/assets/data, consent/capability diff, version pin, migrations і render variants. Підтримана декларативна зміна не вимагає перебудови клієнта.

2 · Client plugin

Build-time механізм Flutter/Dart/native plugin code входить до відповідного app release. Це не те саме, що завантажити VIDA App-пакет після релізу.

3 · Sandboxed executable tier

Окреме рішення WIT/Wasm, native modules або інша execution model потребують власної threat model, policy дистрибуції й compatibility tests. Не плутати plugin ABI з FRB/FFI чи Tauri IPC.

G9 має довести install → capability review → render edit/read-only/moderator/public → update/rollback → safe old-shell rejection на Flutter і Tauri, з однаковими ResourceId, SchemaVersion, правами та provider semantics.

Одна семантика, різні адаптери

Flutter Android/iOS ─ FRB / Dart FFI ─┐ Flutter Windows ───── той самий adapter ─┤ Tauri Windows ─ Rust commands / IPC ────┼─ VIDA application facade Browser ─ worker + Wasm / API ─────────┘ ├─ vida-core: policy, codec, domain └─ vida-runtime: storage, jobs, Iroh, platform ports

Пропозиція до перевірки Facade дає use-case commands, owned DTO, stable IDs, typed error/retryability/safe message key, operation ID, paged snapshot, bounded sequenced events, lifecycle і сумісність. Rust references, locks, DB handles, secrets, allocators та UI toolkit types не перетинають публічну межу.

Команда

start(command, idempotency_key, scope) → operation_id. Довговічний стан і єдиний vault writer — у Rust.

Спостереження

snapshot(scope,generation) + events(after_seq,max_items). Overflow — explicit resync, не мовчазна втрата.

Закриття

cancel(operation_id), unsubscribe/close, suspend/resume/shutdown; один terminal result. GC і закриття WebView не визначають correctness.

Release tuple

Pin Rust + schema/codec + Iroh + FRB/Dart + OS toolchains + Tauri/plugins + WebView2 floor + Wasm hash; version mismatch — typed failure.

FRB і UniFFI самі по собі не гарантують cancel/ordering. UniFFI є fallback для Swift/Kotlin, не Dart binding. Всі shell release мають пройти golden vectors, N−1/N upgrade/rollback і per-platform conformance. FRB cancel, UniFFI, Tauri IPC, Flutter ABI FAQ.

Браузер — інший runtime і обіцянка

Навіть якщо браузер ділить DOM UI з Tauri, він не успадковує native dart:ffi, filesystem/socket/thread можливості Rust native, стабільний background job або direct Iroh path. Поточний first-party browser/Wasm приклад Iroh використовує relay-only path; це свідчення про цей приклад, не універсальна гарантія для всіх версій. Flutter FFI, Flutter architecture, Wasm target, PWA background, Iroh browser example.

A · Worker + Rust/Wasm subset

Browser storage/network ports; явний relay/service binding; перевірити quota, eviction, multi-tab, offline і keys.

B · Gateway/companion

Тонший web client, якщо browser policy блокує local runtime. Може змінити автономність/довіру — потребує окремого product/security approval.

Непідтримана операція має дати явний reduced-capability результат. Browser parity не можна проголосити через спільну UI-розмітку.

Прототипи: одинадцять гейтів

Один thin vertical slice: message → note → task, schema-defined field/workflow, дві Spaces з revoke, offline edit, search/notification, City Portal booking stub. Аудит корпусу додає перемикання account/Space зі збереженням app stacks; capability-driven і public/moderator/read-only package views; нагадування після shutdown; ту саму business/booking identity через два міста, direct app і public site. Ті самі fixtures/tracing IDs для shell; browser може чесно позначити unsupported.

G1 · Один core/contract

Headless CLI + FRB mobile/Flutter Win + Tauri commands + browser Wasm/API; однакова семантика DTO/error/codec/features. Pass: той самий результат, невідома mandatory feature відхиляється.

G2 · Bridge lifecycle

Burst events, 1/100 MiB paths, 10k records, cancel races, renderer restart, repeated close. Pass: bounded queue/resync, один terminal result, без deadlock/leak, symbolicated crash.

G3 · Mobile OS

На фізичних Android/iOS: network switch, suspend, OS kill/reboot, push permission, key restore. Pass: коректне відновлення і чесний degraded UX; battery/delivery виміряні.

G4 · Trust/identity

Airplane-mode vault, Space/invite, hard deny, revoke, дві Persona, lost-device restore. Pass: local use без registration; немає metadata/secret leak; stale device відхилено.

G5 · Windows bake-off

Однакові release data/workflows/hardware: 100k search, grid, editor, navigation, tray, sleep, install/update. Pass: Tauri матеріально виграє product-critical criterion, інакше Flutter Win лишається baseline.

G6 · Accessibility

VoiceOver/TalkBack/Narrator/NVDA, keyboard, scaling, contrast, Ukrainian IME, selection, reduced motion. Pass: усі критичні journeys без P0/P1.

G7 · Browser boundary

Worker/Wasm, relay-only Iroh, quota/eviction, multi-tab, tab kill, push denied/idle, gateway alternative. Pass: окремі cost/latency/durability і unsupported-case результати.

G8 · Release/security

Signed clean/offline Windows install, Android/iOS release packages, version skew, interrupted update/rollback/restore, redaction canaries, XSS→IPC attack. Pass: typed mismatch, no secret diagnostics, no unauthorized command path.

G9 · Package/UI extensibility

Signed downloadable declarative package; FormSchema/PageLayout/ViewDefinition variants; install/consent/update/rollback; old shell; provider swap. Pass: supported declarative change without client rebuild; same resource/rights across renderers/providers; unsupported variant fails explicitly. Жодне приховане завантаження Flutter plugin code.

G10 · Super-app and durable jobs

10–20 apps; per-app navigation stacks, account/Space switch; selective sync/virtualized feed; reminder due while process/device off. Pass: context restored, bounded catch-up/resync, no stale permission leak, no duplicate or falsely guaranteed reminder.

G11 · City/edge profiles

Same business identity/booking via two city placements, direct app, public site; constrained projection capability map. Pass: placement removal does not delete source, no tenant leak, unsupported browser/edge UI declared. Edge лишається відкладеним профілем, не v1 launch target.

Для Windows міряти release build: p50/p95 cold start/unlock/query/editor, frame stability, весь WebView2 process tree, memory, idle CPU, energy, installed footprint. Пороги обирати до вимірів. WebView2 process model.

Контраргументи й зміни після red team

  1. Always-on Iroh на телефоні: OS policy може зупинити будь-який UI toolkit. Провал G3 може вимагати іншої delivery topology/обіцянки, а не автоматично native UI. Android, Apple.
  2. Одна Rust crate ≠ одна поведінка: FRB, IPC і Wasm мають різні cancel, backpressure, serialization і storage. Потрібні ті самі semantic fixtures та mixed-version checks.
  3. Tauri XSS → privileged IPC: hostile rich text/forum/portal content може бути атакою на commands. Нездатність довести isolation відхиляє Tauri. Tauri security.
  4. Tauri мусить обіграти Flutter Win: порівняння на реальному workflow, offline installer і update/rollback; міряти інженерні зусилля/дефекти.
  5. Composable UX/a11y — stress case: якщо core flow потребує постійних native rewrites, native mobile + UniFFI лишається контрольованим fallback.

Не прототипні провали Це adversarial risks із незалежного red-team digest, не виміряні невдачі VIDA.

Одне пріоритетне питання

Що саме має бути встановлюваним у v1 без оновлення клієнта — лише декларативні схеми, форми, сторінки й ресурси, чи також виконуваний код сторонніх застосунків?

Відповідь визначить trust tier AppInstance, G9 і межу platform shell. Після неї можна узгодити пріоритет платформ v1 та rubric прототипів; Flutter/Tauri не затверджуються літературним оглядом. ADR має спиратися на G1–G11.

Інші відкриті рішення — пізніше, окремими контурами

Browser як full offline client чи companion; Windows pre-login service; desktop UX/a11y/performance thresholds; authority для City Portal booking/profile/availability/notifications; compatibility/recovery window; довгострокова підтримка Dart + TypeScript + Rust. Історичні пропозиції в сирому корпусі не відповідають за користувача.
