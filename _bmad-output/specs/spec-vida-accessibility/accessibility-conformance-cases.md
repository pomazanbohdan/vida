# Accessibility conformance cases — planned, not executed

`A` = approved Windows requirement (`REQ-CLIENT-006`, `NFR-PLAT-006`, `ADR-0020`); `C` = candidate from [draft PRD NFR-6](../../planning-artifacts/prds/prd-vida-2026-09-22/prd.md) and [discovery UX Accessibility Floor](../../planning-artifacts/ux-designs/ux-vida-2026-09-22/EXPERIENCE.md). `C` cases need explicit scope approval before they become a release gate. The [Windows shell suite](../spec-vida-windows-shell/windows-shell-conformance-cases.md) remains the detailed Windows oracle: A11Y-F01–F04 trace WIN-F02–F07 and do not replace them.

| ID | Basis | Journey / input | Required observable result |
|---|---|---|---|
| A11Y-F01 | A | Use only a keyboard to enter each Windows Core App, create or edit one Resource, navigate a list/board, send a Message and recover from an error. | No pointer-only action or keyboard trap; focus is visible and the active Persona/Space is identifiable. |
| A11Y-F02 | A | Open Windows system menu and tray, switch back to VIDA, suspend/resume or close an allowed window action. | Exposed commands have usable names and expected behavior; committed local work and truthful sync state survive the shell transition. |
| A11Y-F03 | A | Inspect installed Windows build with a supported screen reader through Messenger, Notes and Project primary controls. | Names, roles, values/actions and reading order make the same authorized workflow operable; exact AT/OS versions are recorded. |
| A11Y-F04 | A | With the screen reader, inspect save-pending, saved-local, synced, denied, conflict and failed states. | Announced text distinguishes these states and their recovery action; a denied variant/title is not disclosed. |
| A11Y-F05 | C | On Android TalkBack and iOS VoiceOver, complete first run, open a chat, edit a note and change a task. | Controls, headings, lists, resource ownership, errors and available actions are navigable and announced on real installed builds. |
| A11Y-F06 | C | Share a Note/Section, then compare conflicting task/file variants with screen reader and keyboard where supported. | Recipient/scope, both permitted variants and each applicable authorized choice are perceivable by name; inaccessible variants remain absent. |
| A11Y-F07 | C | Change from local save to sync, mailbox, recipient delivery, conflict or call reconnect/failure while a screen reader is active. | Text and accessible state/announcement convey the new fact once without conflating it with a different delivery or authority stage. |
| A11Y-F08 | C | Open/close dialog, permission explanation, conflict comparison, share preview and call surface. | Focus and accessibility focus return to a predictable meaningful control; failure names the affected item and recovery action. |
| A11Y-F09 | C | Test largest chosen OS text scale, small phone, larger phone, landscape/tablet and resizable Windows window with long localized labels. | Essential controls, current Persona/Space and status remain reachable and legible; fixed bars do not cover focused content. Exact device/font matrix remains open. |
| A11Y-F10 | C | Enable reduced motion and inspect cursor presence, fading remote-edit highlights, loading and status transitions. | Motion is reducible without losing document-change awareness, state text or failure recovery. |
| A11Y-F11 | C | Inspect a call, file, forum, search and empty/error state with platform accessibility tools; record touch-target dimensions and foreground/background contrast on representative mobile controls. | Primary action and current scope are named; color or animation is not the only signal; private titles/snippets are absent where access is denied. Measurements are recorded, but numeric pass thresholds and live-call captions are not assumed. |
| A11Y-F12 | A + C | Record release artifact, platform/OS, assistive technology/version, locale/text scale, result and defect for every selected journey. | Windows approved checks and any later-approved mobile checks have reproducible installed-build evidence; widget-only or framework-only checks are labeled insufficient. |

Reference—not a declared native conformance level: [WCAG 2.2](https://www.w3.org/TR/WCAG22/) supplies technology-neutral criteria for focus, names/roles, status, non-color cues and input; [Flutter accessibility testing](https://docs.flutter.dev/ui/accessibility/accessibility-testing) and [Microsoft Windows accessibility](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessibility-overview) inform test methods. A VIDA standard/level and the exact platform mapping need a separate explicit decision.
