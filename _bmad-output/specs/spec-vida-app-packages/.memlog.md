- (decision) Accepted by user 2026-09-19: a VIDA app is a downloadable and attachable declarative package of schemas and runtime-defined behavior; v1 does not require arbitrary third-party executable code on the client.
- (decision) Accepted by user 2026-09-19: VIDA ships built-in foundational apps using the same composable bricks; Messenger, Knowledge/Notes and Projects/Tasks are the approved standard Space baseline in PROD-COMPOSITION-001.
- (constraint) Inherited: AppPackage defines schemas, relations, commands, workflows, permission declarations and UI/data ports; AppInstance is scoped to Space with its data and grants (PROD-COMPOSITION-001).
- (constraint) Inherited: VIDA Rust core/runtime owns product semantics and authorization; platform shells render UI and integrate OS policy (architecture spine AD-11, AD-12).
- (capability) CAP-1: An authorized user can obtain a compatible external declarative AppPackage and make it available without releasing a new VIDA client; success is loading its declared forms/resources through existing runtime capabilities.
- (capability) CAP-2: A new standard Space receives Messenger, Knowledge/Notes and Projects/Tasks AppInstances from bundled packages; success is all three using the same package-instance contract as an external package.
- (capability) CAP-3: The same package can be activated in distinct Spaces without merging ownership, data, grants or sync state; success is separate AppInstances with stable package identity and isolated Space-owned resources.
- (constraint) v1 non-goal: arbitrary Dart, native, JavaScript or Wasm code shipped as a downloaded client plugin; declarative rules and workflows may reference versioned runtime capabilities, not silently add executable primitives.
