# Diagnostics candidate fixtures — not executed

These cases distill [PRD FR-35](../../planning-artifacts/prds/prd-vida-2026-09-22/prd.md) and the [review-stage diagnostics requirements](../../../docs/02-requirements/diagnostics-feedback-requirements.md). They do not resolve `OQ-0079` or claim a support channel exists. Use distinct canary strings/IDs in messages, notes, files, contacts, keys and each Persona; inspect both user-visible output and generated bytes.

| ID | Scenario | Required observable result |
|---|---|---|
| DIAG-F01 | While offline, trigger a recoverable failure/crash in Persona A and create a local report; switch to Persona B and create another. | Each report can be previewed locally; A's report does not include B's evidence. Creation alone produces no network transfer. Local storage protection is tested per OS, not assumed from a directory name. |
| DIAG-F02 | Preview a report, remove a field, add a user-authored description, then cancel. Repeat after app restart. | The visible preview matches what would be disclosed; cancel leaves no send intent. A prior preview or crash does not become consent to send after restart. |
| DIAG-F03 | With default settings and without any explicit send action, generate reports across crash, restart and online reconnect while observing network/outbox. | No automatic diagnostic upload or send retry is queued from report creation. A user must explicitly initiate disclosure through a channel selected in the future service design. |
| DIAG-F04 | Place distinctive content, contacts, keys, tokens, file paths and raw Persona IDs in crash-adjacent inputs and exception text; create and inspect the default bundle, local diagnostics and error preview. | Message/Note/File content, contacts, key/token material and raw IDs are excluded by default; sensitive canaries do not reappear through stack/context fields or UI/logging paths. Exact allowlist/redaction schema remains open. |
| DIAG-F05 | Create reports from two Personas on one device and compare their default identifiers, labels, file names and any outbound metadata before explicit send. | The default diagnostic surface does not expose a stable identifier that directly joins the two Personas; report creation does not reveal one Persona's existence to the other. |
| DIAG-F06 | Explicitly attempt disclosure, then simulate transport failure or lost acknowledgment through a future approved channel. | UI says local/pending/unknown as supported by actual evidence, never “sent” on an unconfirmed outcome; retry cannot silently create a second disclosure without the channel's approved duplicate-safety behavior. |

OWASP references: [MASVS-PRIVACY-1](https://mas.owasp.org/MASVS/controls/MASVS-PRIVACY-1/) for data minimization/consent, [MASVS-STORAGE-1](https://mas.owasp.org/MASVS/controls/MASVS-STORAGE-1/) for sensitive mobile local data, and the [Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) for excluding secrets/PII from logs. These guide negative tests; they do not select a support channel or certify a build.
