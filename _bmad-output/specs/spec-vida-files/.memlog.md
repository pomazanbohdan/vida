- (decision) Distill approved PROD-V1-BUNDLE-001, REQ-CLIENT-007/009/023 and SPEC-BLOB-STORE-001 into a BMad Files kernel. The approved blob contract stays an adopted companion; exact crypto and safe GC frontier remain open.
- (capability) CAP-1 intent: user can browse Files view in each Space and manage a file as addressable resource; success: file has stable ID, versions, permissions and visible local availability state.
- (capability) CAP-2 intent: user can attach one File resource to several messages notes or tasks; success: links reuse resource identity without duplicate payload and each consuming context checks access.
- (capability) CAP-3 intent: user can add a file while offline and later transfer it; success: durable local save includes recoverable staged bytes manifest and outbox intent and survives restart before remote delivery.
- (capability) CAP-4 intent: user can choose when a large file downloads; success: over-limit payload waits for explicit action, manifest remains visible, and failed local save says not downloaded without changing shared state.
- (capability) CAP-5 intent: user can receive a verified interrupted file transfer and resume it; success: corruption is rejected and a resumed transfer never treats unverified chunks as accepted.
- (capability) CAP-6 intent: user can compare conflicting file replacements and preserve an alternative as revision or separate copy; success: incomparable accepted versions remain visible and recoverable without silent winner, revision keeps ID and copy receives new ID under rights.
- (constraint) Large immutable payloads stay separate from signed operation log; manifest binds digest size chunks encryption reference authorization context and retention ownership.
- (constraint) Possession of bytes or ticket is not authorization; fetch copy revision and removal recheck current Space rights and revocation.
- (constraint) Sensitive local and retained payloads must be protected; OWASP MASVS-STORAGE-1 and Authorization Cheat Sheet were rechecked on 2026-09-23; exact crypto profile stays prototype-gated.
- (constraint) Auto-download has configurable size limit and explicit confirmation beyond it; failed write is local not-downloaded state, never a shared manifest mutation or GC proof.
- (constraint) Conflict variants and pins remain recoverable until safe retention frontier; no local resolution or deleted link silently releases last needed copy.
- (constraint) Delete/revoke cannot promise erasure of already exported replicated or backup plaintext; no default convergent encryption without leakage decision.
- (decision) Non-goals for Release 1: general OS folder sync, fixed numerical download threshold, selected digest/chunk/key algorithm, or immediate physical erasure guarantee.
