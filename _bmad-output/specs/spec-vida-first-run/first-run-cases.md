# First-run conformance cases — planned, not executed

Normative baseline: [Core bundle](../../../docs/01-product/v1-replacement-bundle.md), `REQ-CLIENT-012/016/017/024/026/028`, `REQ-APP-002/004`, `REQ-CONTACT-001/005/015`, `REQ-ID-015/016`, `NFR-PLAT-010` and the adopted Persona recovery contract. The [PRD UJ-1](../../planning-artifacts/prds/prd-vida-2026-09-22/prd.md) is a draft and [UX UJ-1](../../planning-artifacts/ux-designs/ux-vida-2026-09-22/EXPERIENCE.md) is discovery context; neither approves a particular screen layout.

| ID | Setup / action | Expected observable result |
|---|---|---|
| ONB-F01 | Install VIDA on Android, iOS or Windows with no account, federation or reachable server; choose a new autonomous Persona. | User can choose Profile visibility and durably stage one private Persona/Personal Space without external registration; protected work remains unavailable until ONB-F03 completes. |
| ONB-F02 | Create a second Persona on the same installation and switch between them. | Active Profile, Space list and available actions change; neither Persona silently reveals the other's Resources or Contacts. |
| ONB-F03 | Start a new Persona; terminate and reopen during the recovery step; try to create a Note before and after confirming separate storage. | The same staged Persona/Space IDs and recovery material resume without replacement; before durable confirmation no protected Note is created or `PersonaCreated` reported. After confirmation the same IDs activate once. The loss warning is shown; confirmation is not described as proof that a separate copy exists. |
| ONB-F04 | Attempt to restore with missing or invalid recovery material on a replacement Device. | No private Space is revealed and no new Persona is presented as the restored original; detailed restore proof remains in the recovery spec and `OQ-0024`. |
| ONB-F05 | Inspect a new standard Personal Space before activation. | Messenger, Knowledge/Notes and Projects/Tasks packages and instances are provisioned, but mere provisioning creates neither visible tabs nor grants. |
| ONB-F06 | Read the user-value explanations, activate Messenger and Notes at first run, defer Project, then activate Project in Settings. | Choices are understandable without package terminology; initially selected Apps work; Project activation later needs no client reinstall or new Personal Space and does not reset Messenger/Notes data. |
| ONB-F07 | Decline system Contacts permission and do not connect a cloud address book. | Setup completes; a canonical local Contact Card can still be created and used. |
| ONB-F08 | Choose an address-book connector for the first time. | Default direction is read/import; export or two-way requires explicit choice and a preview before external create/update/delete. Permission refusal causes no local card loss. |
| ONB-F09 | On supported Android, decline optional high availability, then enable and disable it in Settings. | Normal sync/reconnect remains available when OS permits; mode change is limited to that Device/Persona, explains costs and leaves committed local work intact. |
| ONB-F10 | Suspend the iOS client while it is only push-reachable. | Device is not counted Online without an active controlled VIDA connection; first run never promises continuous reachability. |
| ONB-F11 | After setup, create a note while offline, wait for durable local commit, terminate and reopen VIDA. | Note is available with “Збережено локально”; failed commit is not labeled saved, and no independent replica means no “Синхронізовано” claim. |
| ONB-F12 | Choose the optional first-collaboration route: share one Note/Section or start a team Project. | Note/Section route previews and grants only its scoped Resource; team Project route explicitly creates/selects a Shared Space and never converts Personal Space by implication. |
| ONB-F13 | Run the first-run slice on Android, iOS and installed Flutter Windows builds. | Each platform can perform F01, F03, F06, F07 and F11; no platform passes by testing only a mock or another platform's shell. Full Release-1 journey additionally follows `REQ-CLIENT-024`. |

Security evidence is not complete until device builds are tested for recovery-secret storage and logging, optional permission minimization, Persona isolation and denied/invalid restore under the relevant [OWASP MASVS storage](https://mas.owasp.org/MASVS/controls/MASVS-STORAGE-1/) and [privacy](https://mas.owasp.org/MASVS/controls/MASVS-PRIVACY-1/) controls. The cryptographic and platform-specific test procedures remain separate decision/prototype work; this table is not proof of compliance.
