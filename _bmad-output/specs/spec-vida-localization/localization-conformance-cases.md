# Release-1 localization candidate fixtures — not executed

The [approved requirement](../../../docs/02-requirements/localization-requirements.md) owns the locale list and normative behavior. A fixture is passed only with installed-build evidence on Android, iOS and Windows; this document is a test design, not a release claim.

| ID | Scenario | Required observable result |
|---|---|---|
| L10N-F01 | Enumerate all 21 approved locale profiles and traverse bundled shell, Messenger, Notes/Knowledge, Projects, Contacts, Files, Forums, Calls and system/error routes in each installed client; include Windows system menu/tray actions. | No required route or platform action lacks a declared localized label; artifact/version and screenshots/accessibility snapshots are recorded per platform and profile. |
| L10N-F02 | Select language independently of country, then change country, Persona and Space while retaining language; restart offline. | Language follows explicit selection and persists; no country action silently changes Persona, legal regime or data location. |
| L10N-F03 | Resolve BCP 47 exact, regional and missing-key fallback; inject an unsupported locale and absent package key. | The same deterministic declared fallback is used on all clients; Russian is never an implicit fallback; a missing critical string fails the gate rather than appearing as a raw key. |
| L10N-F04 | Exercise Arabic navigation, back/forward affordances, directional icons, mixed-direction names/IDs and modal confirmations. | Text/layout/navigation and direction-sensitive icons mirror where appropriate, while non-directional icons, immutable IDs and user content remain intact; keyboard and screen-reader order is coherent. |
| L10N-F05 | Enter, edit, search and display Japanese, Korean, Simplified and Traditional Chinese in chat, notes, tasks, contacts and files. | IME composition is not prematurely committed; glyphs/wrapping remain legible and local search finds expected tokens after restart/reindex. |
| L10N-F06 | Automate zero/one/few/many quantities, grammatical variables, dates, time, decimal/group separators, units and sorted lists across all 21 approved profiles; visually inspect representative device layouts separately. | Every profile passes its locale-aware ICU data/forms oracle; untranslated string concatenation does not produce broken or ambiguous messages. Representative screenshots do not substitute for all-profile formatting coverage. |
| L10N-F07 | Run missing/obsolete-key, placeholder-type/count, plural-completeness and pseudo-localized expansion checks; capture small-screen and Windows keyboard/screen-reader views. | CI fails incompatible catalogs; no clipped critical control or inaccessible warning passes visual/accessibility review. |
| L10N-F08 | Audit store listing, onboarding, privacy/security, recovery, permission and destructive-action notices for all supported profiles in the release candidate. | Reviewed translations are present and associated with release artifact; missing/unreviewed safety text blocks public release. |
| L10N-F09 | Install AppPackages declaring a locale subset and fallback; activate under a non-supported locale and change locale offline. | Host shows the package's actual fallback language before/when rendering; package cannot silently claim full coverage. |
| L10N-F10 | Replay the same seeded signed resource operation before/after language switch and a translation-only update. | Schema, permission and operation IDs, canonical signed payload bytes and domain result remain unchanged for the identical fixture input; no locale-specific logic fork is introduced. |

The suite does not set a source-locale vendor, sample-device count or resource threshold. Those require implementation-plan evidence, not a new product decision here.
