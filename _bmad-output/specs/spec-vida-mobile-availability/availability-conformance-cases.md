# Mobile availability conformance — candidate fixtures

These are **unexecuted** semantic cases for `CAP-1..4` and `NFR-PLAT-009..012`. Run against installed Android/iOS release builds and a Windows control, not merely headless transport mocks. Capture OS/API version, Persona profile, app lifecycle, network/direct/relay path, authenticated VIDA proof age/issuer, retry state, durable outbox frontier, public count, owner-visible label, battery/data observations and failure reason without raw device IDs, endpoint addresses or content in reports. Numeric pass thresholds remain `OQ-0064/0067/0076`.

| ID | Scenario and injection | Required observation |
|---|---|---|
| AV-F01 | Iroh endpoint reaches relay bootstrap, but no authorized VIDA peer handshake succeeds. | `Endpoint::online()` alone never makes a peer/profile online or a pending operation synchronized. |
| AV-F02 | Address Lookup returns a valid but stale peer address; direct dial fails, relay path later succeeds. | Lookup is not liveness proof; online appears only after fresh authenticated VIDA sync-capability proof over the usable path. |
| AV-F03 | Switch Wi-Fi/mobile network while a direct or relay connection runs; repeat with recoverable migration and with all paths lost. | `VidaNodeHost` signals network change and allows Iroh healing/migration before app reconnect. The public count reflects only current proof; owner may see reconnecting. No path change fabricates an application receipt. |
| AV-F04 | Direct and relay paths fail, then relay returns; test new network, proven connection, foreground and explicit retry during bounded backoff. | Pending outbox persists; retry is bounded/jittered. New network or proven connection resets backoff; foreground and explicit retry trigger prompt path re-evaluation without an invented universal timer reset. Public count excludes a device without proof; reconnecting details remain owner-only. No duplicate business operation after reconcile. |
| AV-F05 | Android baseline under Doze/App Standby: eligible consented Public profile receives FCM wake hint; WorkManager runs later. | Wake is an opportunity to reconnect/reconcile, not a continuous connection or sync receipt. If OS defers work, UI/presence remains truthful and durable intent survives. |
| AV-F06 | Android high-availability is declined, enabled, then disabled on one device; exercise background-start denial, required service type, user-visible notification and current platform time limits. | Baseline remains functional when declined/denied/stopped. Opt-in does not claim an OS exemption; only a supported service profile may run and Google Play policy is rechecked before each submission. Other devices and Personas are unaffected. |
| AV-F07 | Android release build starts the Iroh 1.2 endpoint with DNS resolver under the chosen panic strategy. | JNI DNS context is initialized before endpoint construction or an explicitly tested alternative resolver is used; no hidden panic/fallback dependence under `panic=abort`. This is an Iroh API integration gate, not a background privilege. |
| AV-F08 | iOS app backgrounds, is suspended, receives eligible APNs background hint, then resumes foreground. | Suspended/push-reachable device is absent from online count. Bounded OS wake may reconcile; only active client with fresh authenticated VIDA sync-capability proof over a controlled connection can restore iOS online status. Foreground performs fresh path/proof/reconcile checks; Apple App Review policy is rechecked before each submission. |
| AV-F09 | User force-quits iOS client; force-stops Android client; reopen after remote operations accumulated. | No continuous-online promise or receipt while stopped. On relaunch, restore runtime/endpoint safely, pull/reconcile missed work and avoid duplicate apply. Push delivery is not assumed after force-quit. |
| AV-F10 | Create Autonomous anonymous Persona, then explicitly activate separate Public Persona; opt in to Public push on one device only. | No external push token, wake handle or call-routing binding for anonymous; Public preview/consent is per device; tokens/logs cannot link or be reused across Personas. Anonymous inbound is described as directly reachable only. |
| AV-F11 | Current device, second user-controlled device, bot, ServicePrincipal and AppCenter peer are reachable for one Persona; another Persona exists on same handset. Expire/replay/revoke one proof. | Count includes only fresh user-controlled devices of the viewed Persona; bot/ServicePrincipal/AppCenter are separate, other Persona not aggregated, stale/replayed/revoked proof excluded. Raw endpoint/device list is not exposed by the count. |
| AV-F12 | One-device Persona gains fresh reachability proof but no independent authorized durable replica; later replica applies one operation and issues application receipt. | Profile may be online before its operation is synchronized; `Synchronized` appears only for the declared replication scope after receipt, never from QUIC ACK, mailbox storage or same-Persona business vote. |
| AV-F13 | Lose connection after local commit and during pull; restart, receive duplicate signed operation and causal gap. | Stable IDs/outbox persist, gap repair/reconcile resumes from durable state, duplicate apply does not create a new command or effect, and app status stays distinct from delivery/authority. |
| AV-F14 | Show a visible ordinary profile and a visible anonymous profile to their respective authorized viewers; change each profile's online user-device count. | Every viewer permitted to see a profile sees that profile's exact count, including anonymous-profile viewers. Neither view reveals another Persona's count, raw device/endpoint list or cross-Persona linkage; privacy timing/cadence remains an open measured policy. |

Source boundary: [Android foreground-service restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [foreground-service types](https://developer.android.com/develop/background-work/services/fgs/service-types) and [FCM priority](https://firebase.google.com/docs/cloud-messaging/android-message-priority) constrain AV-F05–07; [Apple background execution](https://developer.apple.com/documentation/uikit/preparing-your-ui-to-run-in-the-background) and [APNs background updates](https://developer.apple.com/documentation/usernotifications/pushing-background-updates-to-your-app) constrain AV-F08–09. [Iroh 1.2 Endpoint API](https://docs.rs/iroh/1.2.0/iroh/endpoint/struct.Endpoint.html) distinguishes endpoint/bootstrap/address and documents Android DNS/JNI setup; [Iroh Address Lookup](https://docs.iroh.computer/concepts/address-lookup) resolves dial information, not current application reachability. These primary sources describe available mechanisms, not measured VIDA outcomes.
