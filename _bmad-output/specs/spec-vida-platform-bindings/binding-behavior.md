# OQ-0035 binding behavior and conformance plan — draft

The behaviors below are **proposed boundary refinements and fixture plans**, not a selected native FFI/Web Rust-Wasm bridge or passed implementation. The adopted documents in `SPEC.md` control if a proposal conflicts with an approved invariant.

## Boundary ownership

| Boundary | Owner | Never inferred from the bridge |
|---|---|---|
| Flutter presentation | Render, navigation, accessibility, user intent and per-OS adapters. | Button enabled ≠ permission; active connection ≠ delivery or authority. |
| `vida-sdk` facade | Versioned commands, queries, owned DTOs, bounded observations and typed failures. | Generated binding type ≠ public domain or wire schema. |
| `vida-runtime` | Durable jobs/outbox, local writer, recovery, sync, Iroh/NodeHost and platform-port orchestration. | UI lifetime ≠ operation lifetime; transport ACK ≠ domain apply. |
| `vida-core` | Deterministic command validation, authorization, transition and signed-operation validation. | Arrival order, Dart clock or widget state ≠ accepted order. |
| Platform ports | OS secure-store handles, lifecycle/wake, notifications, permission prompts, file picker and installed-app packaging. | A Flutter isolate or plugin ≠ background-execution exemption. |

The stable boundary is semantic. A generated Dart API may change physical representation without changing `ContractId` meaning. One effective writer per local vault is required even if multiple windows/processes contend; exact ownership/attachment implementation and runtime-instance granularity across **different** Persona vaults remain prototype decisions.

## Candidate contract to prove

1. **Submission:** a coarse domain command carries actor/scope, idempotency context and typed input. A proven pre-commit failure may return typed refusal; once commit outcome could be ambiguous, the facade retains the stable operation identity and reports unknown/pending until recovery reaches its required frontier and authoritative lookup resolves that ID. A missing callback or pre-commit observer event cannot prove “збережено локально”; a verified whole-action durable result must include every required staged attachment. Local commit remains separate from later replication, delivery, authority and external-effect receipts. Exact DTO fields and commit-result shape remain open.
2. **Observation:** authorized paged snapshots and bounded ordered events expose a generation/sequence or equivalent proof of gaps. On overflow, observer recreation or lost process memory, the shell receives `resync_required` (or a semantically equivalent typed signal) and reloads an authorized snapshot. A Dart `Stream` alone does not prove these guarantees.
3. **Cancellation:** the Rust runtime owns an explicit cooperative cancellation token or operation command. Closing a Dart `Future`, widget or observer does not undo a committed operation. The resulting terminal state and whether cancellation is still possible must be observable; no cancellation may create a second domain apply.
4. **Ownership and threading:** DTOs are owned copies or explicitly bounded value handles. Long-lived opaque resources require explicit `close`/`dispose`; a finalizer is only a safety net. Rust-owned tasks and the local writer outlive a transient screen; UI callbacks are dispatched without Rust locks held and never block the Flutter UI thread. Stale handles after shutdown/reopen fail with a typed error.
5. **Errors:** the boundary preserves at least validation, authorization, conflict, durability/quota, transport/lookup, lifecycle, cancellation, compatibility and internal-fault categories. The UI receives a safe message key, retryability and correlation reference where useful; secret-bearing debug details remain inside redacted diagnostics. A panic does not unwind across FFI.
6. **Large data:** small DTOs are bounded; file/blob bytes use a measured chunk/stream or verified content-reference path, not thousands of chatty getters or an unbounded in-memory message. The transfer still passes Core authorization and ownership checks.
7. **Compatibility:** the installed artifact records Rust revision, `vida-sdk`/`vida-contracts` version, generated binding, Flutter/Dart toolchain, target ABI and relevant persisted/protocol profile. Initialization rejects a mismatched mandatory contract before calls. The exact supported mixed-version range belongs to OQ-0037, not this draft.

These are a **testable candidate shape** distilled from the [2026-09-19 UI/binding research](../../planning-artifacts/research/technical-vida-ui-platform-and-rust-binding-strate-2026-09-19/research.md), narrowed by Flutter Windows [ADR-0020](../../../docs/03-architecture/decisions/ADR-0020-flutter-windows-in-release-1.md) and the later static-Web [ADR-0021](../../../docs/03-architecture/decisions/ADR-0021-static-web-client-in-release-1.md). The older Tauri bake-off is not a Release-1 alternative; its browser exclusion is superseded. The native fixture plan below does not prove Web.

## Physical bridge candidates and external checks

| Candidate | Evidence to gather | Decision status |
|---|---|---|
| `flutter_rust_bridge` on Android/iOS/Windows | Generated async/stream/error/opaque-handle behavior, package assembly, cancel races, hot/process restart and release-build memory profile. | First prototype candidate only. Its [cancellation guide](https://cjycode.com/flutter_rust_bridge/guides/how-to/cancel) describes application-owned tokens; generated async calls do not make domain cancellation automatic. |
| Direct `dart:ffi` over narrow C ABI | Manual ABI/allocator/callback surface, generated bindings, static/dynamic packaging on each OS, error/stream ergonomics and maintenance cost. | Contingency/control; [Flutter FFI guidance](https://docs.flutter.dev/platform-integration/bind-native-code) describes current `package_ffi`/build-hook packaging, not VIDA correctness. |

Neither candidate supplies authorization, domain finality, crash recovery or lifecycle policy by itself. [OWASP MASVS-STORAGE-1](https://mas.owasp.org/MASVS/controls/MASVS-STORAGE-1/) supports testing that sensitive local state and keys are protected; OWASP does not choose the bridge. Check current upstream versions and store rules again when pinning the release tuple.

The FRB [stream guide](https://cjycode.com/flutter_rust_bridge/guides/types/translatable/stream) permits a Rust `StreamSink` to outlive its creating function; Dart [subscription cancellation](https://api.dart.dev/dart-async/StreamSubscription/cancel.html) stops that subscription, not an independently owned VIDA domain task. The selected bridge must prove producer detachment, boundedness and authorized resubscription rather than infer them from a Dart `Stream` API.

For direct Dart FFI, the [Dart `NativeCallable.listener` contract](https://api.dart.dev/dart-ffi/NativeCallable/NativeCallable.listener.html) makes native-to-Dart callbacks asynchronous and requires pointer-backed arguments to remain valid until callback completion; invoking a callback after `close` is undefined behavior. [Dart `NativeFinalizer`](https://api.dart.dev/dart-ffi/NativeFinalizer-class.html) is not a reliable process-exit cleanup path. Generated bridges must pass the same ownership tests even if they hide these primitives.

[UniClipboard/Engine research](../../planning-artifacts/research/technical-iroh-project-library-inventory-for-vida-2026-09-23/digests/uniclipboard-engine-r6-luna.md) adds a concrete Rust host/core, Iroh infrastructure, lifecycle and UniFFI/N-API reference for these fixtures. The [mobile integration follow-up](../../planning-artifacts/research/technical-iroh-project-library-inventory-for-vida-2026-09-23/digests/uniclipboard-mobile-and-governance-r7-luna.md) finds a pinned native wrapper in UniClip source but separately documented HTTP compatibility behavior for current mobile releases. Source wiring is not release-device proof. Engine remains a pattern, not a tested Flutter Android/iOS/Windows bridge or VIDA generic signed-log provider. Direct reuse would require Iroh-version/fork, file-at-rest, license, maintainer-continuity and installed-client checks under BND-08/BND-10/BND-11.

## Minimum cross-platform fixture plan

| ID | Scenario | Required observable result |
|---|---|---|
| BND-01 | Same command/query in headless harness and three installed release builds. | Same authorized IDs/transitions and typed denial; no shell-side policy fork. |
| BND-02 | Kill before local commit, at commit/result boundary and after commit before UI callback; reopen and query/retry with same stable ID. | No pre-commit observer event yields Saved. An ambiguous outcome remains unknown/pending until runtime recovery reaches its required frontier and authoritative ID lookup completes. Then the UI recovers one committed result or a proven typed failure; it neither reports loss early nor silently submits a new ID. |
| BND-03 | Cancel before commit, while work is pending, at commit boundary and after durable commit. | Explicit terminal/cannot-cancel result; no duplicate apply, rollback claim after commit or silent deletion of pending work. |
| BND-04 | Cancel Dart subscription while Rust producer/callback is in flight; drop observer, overflow bounded event queue, re-enter through callback, switch Persona and restart. | Producer stops or remains safely detached and bounded; gap detected by generation/sequence evidence; authorized snapshot/reconcile restores current projection without leaked/cross-Persona events or an event-loss-as-success state. Subscription cancellation does not undo a committed domain operation. |
| BND-05 | Rapid open/close, stale handle after runtime restart, Dart GC, callback reentry and concurrent windows. | No use-after-free, deadlock, leaked writer, stale-handle success or UI-thread stall; explicit close works independently of GC timing. Two windows on one vault never gain parallel writer authority. |
| BND-06 | Auth revoke while view/search/notification/command are active. | Core denies forbidden action; no stale secret/snippet leaks through event or error DTO. |
| BND-07 | Inject lookup, relay, authorization, quota, schema, panic/internal failure and malformed native error payload. | Stable distinct safe error codes and retry behavior; no key, plaintext or private identifier in Dart-facing diagnostics; panic never unwinds across FFI. |
| BND-08 | Android/iOS suspend, force-stop/kill, wake and network switch; Windows sleep/restart; cut process between local commit, result delivery and observer reconciliation. | Durable work survives, path re-evaluates, state is recovered by stable ID and authorized snapshot; online/pending status does not imply 100% background reachability. |
| BND-09 | Large attachment and 10k-item observation under bounded resources. | Explicit backpressure/chunking or content-ref path; no unbounded DTO copy or event loss masked as success. |
| BND-10 | Mismatched generated code/native binary; unknown mandatory contract feature; approved mixed-version tuple. | Mismatch fails before unsafe call; only declared compatible tuple proceeds. |
| BND-11 | Inspect persisted secrets, pending-operation bytes and crash/error logs on Android, iOS and Windows, including FFI error paths. | No secret or unauthorized plaintext exposed through bridge diagnostics or unprotected local storage; [OWASP MASVS-STORAGE-1](https://mas.owasp.org/MASVS/controls/MASVS-STORAGE-1/) is the security check, not a bridge-selection rule. |
| BND-12 | In a shared Space, test permitted offline reading before the seven-day rights-proof expiry and managed UI/search/export/runtime API/plugin reads after expiry or received revocation; repeat across `standard`/`protected`/`critical`, Owner and other roles on Android, iOS and Windows, with restart, clock rollback and stale control-head replay. | Every managed shared read surface, including already-open content, locks at expiry or effective revocation and stays locked until valid fresh rights reconciliation; stale persisted state cannot reopen it. Personal Space Owner remains a separate case. This fixture does not choose the OQ-0053 proof/anti-rollback mechanism. |
| BND-13 | Send declared-boundary integer extremes/overflow, unknown enum or tag, absent versus null/default fields, malformed and edge-length Unicode through the headless harness and all three release builds. | Values round-trip or fail by the versioned `ContractId` policy without truncation, lossy coercion, panic or cross-platform disagreement; an unknown mandatory meaning cannot become a valid default. Exact DTO field set and numerical bounds remain an OQ-0035 choice. |
| BND-14 | Transfer a large attachment across awkward chunk boundaries; cancel, close/reopen, switch observer or force Dart GC while a native buffer/callback is in flight, then retry after process restart. | Buffer and callback ownership remain valid; normal close releases resources once without use-after-free, while abrupt exit recovers from durable state rather than relying on finalizers. Final length/digest/manifest validation agrees with the [device sync contract](../../../docs/04-specifications/device-sync-session.md); partial bytes are never reported complete, and retry does not duplicate a domain operation. The chosen bridge must prove this in installed builds. |
| BND-15 | Start one offline command whose result includes two required attachments; fail the second stage or kill after first stage/before complete logical publication. Repeat with pre-commit observer delivery and post-commit callback loss. | UI marks the **whole** action Saved only after atomic durable commit of `OperationEnvelope + SyncLog + outbox + required local bytes` and recovery of the associated dedupe/origin frontier. Unreferenced staged bytes may remain but no partial published action or dangling reference does; restart by stable ID reconstructs the committed outcome or explicit pending/failed state. |
| BND-16 | Separately test two shell windows and two independent runtime processes opening the same Persona vault. Race commit; suspend writer A, attempt B attach/takeover, resume A and attempt its old-handle write. In another run kill A, then reopen B and recover; also test orderly close/reacquire. | Exactly one effective vault writer. If B cannot take over, it gets typed busy; if B takes over, resumed A is fenced and its stale write fails typed—never a second commit or stale frontier. Killed A has no callable handle; fresh B recovers pending outbox/original ID without duplicate apply. Test distinct Persona vaults only as evidence until cross-vault runtime topology is decided. |

Fixtures are not yet executable and no bridge has passed them. Numerical queue/buffer limits and performance budgets require a representative vertical slice and the platform resource gate.

### Web parity addendum — candidate fixtures

| ID | Scenario | Required observable result |
|---|---|---|
| BND-W01 | Apply the same seeded Persona/Resource command through headless Rust, Android native binding and Web Rust/Wasm facade. | IDs, authorization, canonical operation bytes, durable-result classification and projection agree; Web shell does not own a second domain implementation. |
| BND-W02 | Cache complete Flutter/JS/Wasm assets, create a pending local operation, close the tab and reopen offline. | One compatible artifact tuple reopens its browser vault and pending operation, or reports a truthful quota/eviction/key failure; a mixed cached tuple fails before unsafe calls. |

Web tests supplement BND-01–16, not replace native release-build proof. Their Rust/Wasm bridge, browser key custody and storage provider remain OQ-0035/0036 decisions under ADR-0021.
