# Portable export candidate conformance cases — not executed

These cases derive from PRD FR-36, REQ-OPEN-007, SPEC-ID-009, Resource Domain CAP-6 and the platform security baseline. They specify observable outcomes, not an archive format or cryptographic primitive.

| ID | Scenario | Required observation |
|---|---|---|
| PORT-F01 | Export a Personal Space containing historical schema versions, a Note, Task, File bytes and Relations linking them. | The authorized reader recovers every included category and stable relation/target identity; no category is silently dropped. |
| PORT-F02 | Export permitted shared content whose Task links to a private File or Note that the exporter cannot read. | The protected target's bytes, title and other private metadata do not appear merely because its relation is visible; current target authorization is checked. |
| PORT-F03 | Switch between personal and corporate Personas in one LocalVault, then export the personal context. | The corporate account's dependent Resources, keys and metadata are absent unless separately and explicitly authorized; no cross-Persona correlation is created by default. |
| PORT-F04 | Receive effective shared-Space revocation, or pass seven days without authority-confirmed rights reconciliation, then request export on each Release-1 client. | Managed export read is denied until valid rights proof; process restart or stale control-head replay does not reopen it. |
| PORT-F05 | Copy the package to a clean machine without VIDA account or paid credentials; use the published independent reader and valid recovery material. | The reader opens the supported version and reconstructs included schemas, Resources, Relations and File bytes; no hidden service, private SDK or paid extension is required. |
| PORT-F06 | Try a wrong recovery secret, damaged ciphertext or modified manifest/payload. | Protected content is not exposed and the reader reports authorization/integrity failure rather than silently accepting altered data. Exact crypto vectors await the chosen profile. |
| PORT-F07 | A selected File exists only as remote metadata, or local storage fills while creating the export. | No complete package is claimed; the authorized user receives an explicit failure/incompleteness result, and the last recoverable copy is not deleted. Whether a partial package may be retained or read remains open. |
| PORT-F08 | Kill the client at deterministic cuts during staging, encryption and final output, then restart. | No interrupted artifact is presented as complete; retry/recovery does not silently omit previously selected data or leak plaintext staging files. |
| PORT-F09 | Open a package with a compatible older/newer independent reader and with an unsupported mandatory format feature. | Version/capability mismatch is explicit; mandatory unknown content is not silently discarded or misinterpreted. Exact compatibility window remains open. |
| PORT-F10 | Inspect local temporary files, OS share/cache locations, backups, diagnostics and logs after export on Android, iOS and Windows. | Protected plaintext and recovery secrets are not exposed outside the authorized flow; platform-specific evidence is recorded. |
| PORT-F11 | A clean-room reader is built from only the public schemas, versioned export specification and published fixtures. | It opens a supported encrypted test package after authorization without private VIDA contracts or paid credentials; the official Release-1 claim requires this independently distributed reader and public artifacts. |

Security cross-checks: [OWASP MASVS-STORAGE-1](https://mas.owasp.org/MASVS/controls/MASVS-STORAGE-1/) covers sensitive mobile storage; [Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html) covers protected data and keys; [Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) requires deny-by-default and checks for each request. They do not select VIDA's archive format or key-recovery design.
