# OQ-0036 provider evidence — 2026-09-23

This is a dated candidate comparison, not a provider ADR. The VIDA contract and `STO-01..19` in `storage-behavior.md` control; official library documentation establishes advertised mechanisms, not passing VIDA fixtures on Android, iOS or Windows. Versions below are snapshot observations, never a `<1.0` exclusion rule.

| Candidate | Supported mechanism and likely fit | Unproven cost or risk for VIDA |
|---|---|---|
| SQLite + Rust binding; optional SQLCipher | Transactions, SQL and [FTS5](https://www.sqlite.org/fts5.html) fit indexed projections/search. In WAL mode, [FULL syncs the WAL per commit; NORMAL can lose the latest committed transaction after OS crash or power loss](https://www.sqlite.org/pragma.html#pragma_synchronous). [Online Backup API](https://www.sqlite.org/backup.html) supports a consistent live copy. SQLCipher [encrypts database pages and WAL/journal page content](https://www.zetetic.net/sqlcipher/design/). | Build/VFS/fsync behavior and crypto configuration on each target; live backup publication, WAL checkpoint, separate blob store, wrapped-key recovery and protected search artifacts. SQLCipher does not encrypt other transient files, so file-based temp storage must be disabled in the candidate build and actual release artifacts inspected. A successful SQLite call alone does not prove physical-device power-loss safety. |
| [redb](https://docs.rs/redb/latest/redb/) | Embedded pure-Rust B-tree KV with serialized writer and concurrent readers. [Immediate durability](https://docs.rs/redb/latest/redb/enum.Durability.html) is the candidate commit setting for a saved badge; recent [releases](https://github.com/cberner/redb/releases) and [issues](https://github.com/cberner/redb/issues) show ongoing maintenance. | No built-in SQL/FTS or native at-rest encryption identified in its public API; projection/search and key protection are VIDA-owned. Android/iOS runtime, filesystem locking, backup and recovery fixtures are not proven by the docs. |
| [Fjall](https://docs.rs/fjall/latest/fjall/) | Embedded pure-Rust LSM KV with keyspaces and transaction-capable API; [PersistMode](https://docs.rs/fjall/latest/fjall/enum.PersistMode.html) distinguishes app-crash recovery (`Buffer`) from OS/power durability (`SyncData`/`SyncAll`, subject to filesystem guarantees). [Releases](https://github.com/fjall-rs/fjall/releases), [changelog](https://github.com/fjall-rs/fjall/blob/main/CHANGELOG.md) and [issues](https://github.com/fjall-rs/fjall/issues) are active source surfaces. | Choose transaction API and sync policy explicitly; generic atomic batch is not automatically a read-modify-write transaction. No SQL/FTS or native at-rest encryption identified; compaction, mobile file lifecycle, backup and fault behavior need the common fixtures. |

## Candidate-gate sequence

1. Freeze one VIDA logical corpus: Messenger message/outbox, collaborative note, task conflict, file manifest and private search projection; include pending operations and old schema fields.
2. Run `STO-01..19` against the actual release binaries and storage directories on Android, iOS and Windows. Record effective settings, build provenance, transaction API, durability policy and failure classes; do not infer mobile support from pure-Rust code alone.
3. Compare recoverability and privacy **before** throughput, startup, size and battery. An alternative KV provider may use a separate rebuildable search projection, but the complete adapter must pass the same user-visible contract.
4. Only then propose a provider tuple and ADR. A benchmark or commit/release count alone is not acceptance; open issues need defect-specific assessment, not a snapshot popularity score.

## Source/uncertainty notes

- SQLite [PRAGMA](https://www.sqlite.org/pragma.html), [WAL](https://www.sqlite.org/wal.html), [Backup API](https://www.sqlite.org/backup.html), [result codes](https://www.sqlite.org/rescode.html) and [FTS5](https://www.sqlite.org/fts5.html) were checked 2026-09-23. `FULL` depends on truthful VFS/filesystem sync; raw copying a live database is not an Online Backup API substitute. `SQLITE_FULL` and I/O errors require checking the transaction state, not assuming a fixed rollback scope.
- SQLCipher [design](https://www.zetetic.net/sqlcipher/design/) and [key material](https://www.zetetic.net/sqlcipher/database-key-material/) were checked 2026-09-23. The design says WAL/journal page data are encrypted but other transient files are not, so a candidate release build must prove file-based temp storage is disabled and inspect actual DB/WAL/journal/temp/search/backup artifacts under STO-15. SQLCipher does not by itself supply VIDA key custody, revocation or a verified portable backup. Licensing and chosen Rust binding/build features remain a separate due-diligence gate.
- redb [API](https://docs.rs/redb/latest/redb/), [durability](https://docs.rs/redb/latest/redb/enum.Durability.html), and Fjall [API](https://docs.rs/fjall/latest/fjall/) were checked 2026-09-23. Release/issue pages indicate development, not correctness or cross-platform certification; pin exact versions before a prototype and re-check their known defects.
