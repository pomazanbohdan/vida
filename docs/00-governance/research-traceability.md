## Відомі конфлікти

- UI: Dioxus відкликано; `.NET/Blazor Hybrid` — стара пропозиція; Android/iOS/Windows Flutter погоджено для Release 1, WinUI 3/C# можливий пізніше.
- Messaging: resolved — VIDA-owned protocols; Delta/Chatmail patterns are reference-only under ADR-0005.
- Storage: signed operation files проти PDM + deterministic CBOR; фінальний contract не затверджено.
- Iroh: core 1.2 accepted in ADR-0005; higher-protocol adapters, FFI artifact matrix, Address Lookup policy and platform profiles remain prototype scope.
- CRDT: чинний baseline обмежує його workload-specific випадками. Матриця `Status = causal register` у `(10)` була пропозицією; deterministic CRDT winner не доводить фізично першого sync, але дає референс для peer-equal convergence. Пріоритет першого acceptance лишається лише для порівнюваної історії (`REQ-SYNC-004`); конкретний concurrent resolver і granular text/code merge — `OQ-0034`.
- PostgreSQL: відхилений як єдина база, дозволений як server provider/projection.
- Naming: `OwnershipScope` → `Space`; `PersonalVida` → `Vida`.
- App packages: package плюс Space-scoped `AppInstance` прийнято в ADR-0007; маркетплейс VIDA, зовнішні репозиторії та update discovery — в ADR-0008; керована прикладна логіка — в ADR-0009; область дії лише цільового instance/Space — в ADR-0010; пріоритет instance process над базовим тригером і developer-owned композиція — в ADR-0011; межа command/fact/sync — в ADR-0012. Конкретний executor, repo/update format і вибір Rhai/Wasmtime не стають рішенням із research.

## Правило перевірки OWASP для нових кейсів

- Для кожного нового продуктового, архітектурного або технічного кейсу `MUST` перевіряти релевантні матеріали OWASP: MASVS/MASWE/MASTG для mobile; ASVS, WSTG і Cheat Sheet Series для web, API та server. Якщо контроль не застосовується, `MUST` записати причину `not applicable`.
- У research/ADR/специфікації `MUST` вказати точний контроль або рекомендацію, URL, дату перевірки, наслідок для VIDA та тест/обмеження гарантії. OWASP є джерелом вимог і перевірок безпеки, але не автоматично затверджує продуктове рішення або строк дії локального offline-доступу.
- Для локального offline-доступу `MUST` окремо перевіряти session expiry, freshness membership/control state, local cache/key storage і межу дистанційного відкликання; строки web-сесій `MUST NOT` без пояснення переносити на offline-read lease.
