Основні осі відбору — **розвиток**, **частота змістовних комітів**, **кількість реалізованих потрібних VIDA функцій** і **стан issues**. Функції рахуємо тільки в межах однакового provider gate (наприклад, два редакторні CRDT), за наперед визначеним переліком; ширина всього VPN-застосунку не порівнюється з вузькою FFI-бібліотекою. Для issues окремо фіксуємо open/closed, вік, критичність і підтверджену реакцію, не змішуємо їх із PR. Далі перевіряємо тести/CI, exact lockfile tuple, ліцензію, безпеку та upstream caveats як обов'язкові умови. [Поглиблений зріз](../_bmad-output/planning-artifacts/research/technical-iroh-project-library-inventory-for-vida-2026-09-23/research.md) додає профілі Irokle/iroh-db/Wyrd/Kukuri, Loro/Automerge, Arachne/freeq/iroh-live/Proscenium, Rayfish/Nexa/RDS/iroh-ffi. Наприклад, Rayfish має широкий функціонал і 73 відкриті issue, а RDS — швидку розробку, але лише близько двох днів публічної історії; ні те, ні інше не є самостійним verdict. Wyrd має аномально багато сирих комітів, що потребує розкладання за змістом. Відсутні GitHub API значення позначаємо «невідомо», не нулем; зріз оновлюємо перед бібліотечним ADR.

[Матриця file-transfer](../_bmad-output/planning-artifacts/research/technical-iroh-project-library-inventory-for-vida-2026-09-23/digests/file-transfer-feature-coverage-r5-luna.md) окремо звіряє `iroh-blobs`, Ringdrop, Wyrd і RDS; [матриця network/mobile/FFI](../_bmad-output/planning-artifacts/research/technical-iroh-project-library-inventory-for-vida-2026-09-23/digests/network-feature-coverage-r4-luna.md) розділяє endpoint, Android lifecycle і binding функції. ## Рекомендований наступний крок

Порівняти не репозиторії «загалом», а 5 незалежних provider gates: signed log/storage, editor CRDT, file transfer, group security, Flutter/Rust+mobile lifecycle. У кожному — 2–3 кандидати й однакові VIDA fixtures. Для вечірнього cluster окремо додати agent process ownership, application RPC receipt/authorization, browser relay-only recovery, C ABI lifecycle і durable inbox/restart; для 24.09 — device-sharing pairing/SAS/allow-list, desktop privacy schema та embedded device→host telemetry; для 25.09 — remote-desktop permissions/identity/reconnect, CAS/ref authority й окрему межу design-vs-implementation для Ultra-Netz; для 27.09 — ACP process/EndpointId admission, Router/multi-ALPN application bus, host-ordered collaboration, agent hub authority і bridge-backed typed RPC compatibility. Для `UniClipboard/Engine` перевірити host/core boundary, bindings, process lifecycle, file-at-rest, Iroh 1.2 compatibility і release provenance; не включати його до signed-log provider race без доказу generic resource contract. [Розгорнуті висновки, докази та невирішені питання](../_bmad-output/planning-artifacts/research/technical-iroh-project-library-inventory-for-vida-2026-09-23/research.md); сирі source digests лежать поруч. Ліцензійний аналіз Engine Apache-2.0, окремого app AGPL-3.0 та транзитивних залежностей передбачати до reuse; архітектурні патерни можна досліджувати без перенесення коду.
