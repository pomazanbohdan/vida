Домовились. Працюватимемо не як із простими конспектами, а як із фіксацією актуального стану проєкту та прийнятих рішень.

Для кожного чату я:

1. Витягну дослідження, вимоги, порівняння та запропоновані варіанти.

2. Відокремлю:

   * підтверджені факти;
   * запропоновані технології;
   * попередні припущення;
   * суперечливі або застарілі рішення;
   * відкриті питання.

3. Поставлю тобі конкретні запитання щодо вибору, наприклад:

   * `Iroh залишається основою синхронізації чи лише кандидатом?`
   * `Rhai приймаємо для прикладної логіки, а Wasmtime — для ізольованих плагінів?`
   * `Microsoft Duroxide прийнято як основний вбудований рантайм чи потрібен прототип?`
   * `Які альтернативи потрібно залишити в документі, а які остаточно відкинути?`

4. Після відповідей сформую фінальний документ із чіткими статусами рішень:

| Статус             | Значення                                    |
| ------------------ | ------------------------------------------- |
| Прийнято           | Частина цільової архітектури                |
| Для прототипування | Потрібна практична перевірка                |
| Кандидат           | Рішення ще не ухвалено                      |
| Відкладено         | Може знадобитися пізніше                    |
| Відхилено          | Не використовуємо, із зазначенням причини   |
| Замінено           | Було актуальним, але з’явилося нове рішення |

Кожен документ матиме структуру:

* призначення;
* актуальні вимоги;
* прийняті рішення;
* цільова архітектура або модель;
* технологічний стек;
* важливі результати дослідження;
* відхилені альтернативи та причини;
* відкриті питання;
* ризики й обмеження;
* наступні перевірки або прототипи;
* дата актуалізації.

Додатково варто створити два загальні файли:

* `00 — Індекс проєкту` — навігація між документами;
* `01 — Реєстр архітектурних рішень` — коротка таблиця всіх прийнятих, замінених і відкритих рішень.
